1.Agent.java:184` 的 `try-catch` 为什么要包整段 `think()`？如果不 catch 会怎样？
  think() 的 try-catch — 因为 think() 是用户自己写的抽象方法，框架无法预知异常，必须兜底。不 catch 会导致 agent 线程崩溃、通信中断、该 agent 在仿真中失去响应。

2.项目中为什么各处都打日志？日志的 4 个级别分别对应什么场景？
  - 无法复现 — 火灾蔓延、建筑倒塌都带随机性，同一场景跑两次结果不同
  - 无法打断点 — 多 agent 分布式并行运行，打断点会破坏时序
  - 只能事后追溯 — 回看日志才能还原每个 agent 每步的决策过程
  DEBUG — 详细信息，用于调试。
  INFO — 一般信息，用于正常运行。
  WARN — 警告信息，用于警告。
  ERROR — 错误信息，用于错误。
